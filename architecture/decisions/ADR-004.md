# ADR-004: Issue-Comment JSON State Ledger and Artifact Audit Trail (D4 — State)

## Status

Accepted. (Proposed before any agent code was written; status set after the runs.)

## Context

The workflow requires durable state across retries, restarts, and workflow_dispatch review rounds, as well as transparent human inspection on GitHub. Committing state metadata files directly to the pull request branch pollutes the code diff, confuses the Reviewer, and risks merging internal scaffolding into main.

## Decision

Maintain a single status comment on the target GitHub issue containing a machine-readable hidden HTML/JSON block (`<!-- autose-state {...} -->`) alongside human-readable progress status. This JSON block serves as the single source of truth, tracking the current stage, review round, retry attempt, feature branch name, cumulative token counts, and direct links to each run's uploaded GitHub Actions Workflow Artifacts (spec.md, design.md, diff.patch, test_report.md, pr.md, review.md). The PR branch itself contains exclusively the target repository code edits and new tests. On restart or workflow_dispatch resumption, the orchestrator parses the issue comment's JSON block and resumes from the target stage, rebuilding the working branch cleanly from the pinned base commit whenever Stage 3 runs.

## Alternatives considered

- **Committing .autose/ state files to the PR branch:** Rejected because it clutters the PR diff for both human maintainers and the Reviewer, and risks accidental merge into the main codebase.
- **Relying solely on GitHub Actions cache:** Rejected because cache entries are ephemeral, non-browsable by humans in the GitHub UI, and prone to eviction between review rounds.

## Consequences

- **Good:** Keeps PR diffs completely clean while giving maintainers a single, live-updated audit trail on the issue linking directly to every stage artifact. Makes restarts idempotent and resilient to transient runner failures.
- **Bad:** Concurrent edits to the same issue comment could race if concurrency locks (ADR-010) were ever bypassed, and GitHub Actions artifacts expire after the repository's retention window (default 90 days).
