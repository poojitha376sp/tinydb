# ADR-002: Deterministic State-Machine Orchestration with workflow_dispatch Review Loops (D2 — Control Flow)

## Status

Accepted. Amended by ADR-013 (one test repair before going back to Design). (Proposed before any agent code was written; status set after the runs.)

## Context

The workflow must traverse six sequential stages, enforce validation checks between them, retry failing implementations, and route review feedback back to either Design or Implementation up to two times. Because GitHub Actions jobs cannot natively loop backward to an earlier job, the control plane must handle both intra-job retries (test failures) and cross-job rollbacks (review rejections) without losing state or entering infinite loops.

## Decision

Implement a deterministic Python state machine inside the primary Orchestrator job that invokes Stages 1 through 5 as sequential function calls governed by hard-coded transition rules rather than an LLM router. On test failure in Stage 4b, the state machine routes execution back to Stage 3 (Builder) for at most 3 attempts; if the exact same test failure occurs twice consecutively, it escalates backward to Stage 2 (Design). For Stage 6, the Reviewer outputs structured findings tagged as either code or approach. When changes are requested and the review round is under 2, the Review job triggers a fresh workflow run via workflow_dispatch, passing the issue_number, incremented round_number, and target resume stage (2 or 3) as explicit inputs.

## Alternatives considered

- **Autonomous LLM planner/router:** Rejected because allowing an LLM to dynamically choose the next stage risks skipping mandatory checks, entering unbounded loops, and burning scarce free-tier tokens on routing decisions.
- **Six separate GitHub Actions jobs chained via needs: for all stages:** Rejected because GitHub Actions forbids cyclic needs: graphs, making Stage 4 $\rightarrow$ Stage 3 test-fix loops impossible without spawning a brand-new workflow run on every single unit test failure.

## Consequences

- **Good:** Guarantees deterministic stage ordering, enforces hard bounds on test retries (3) and review rounds (2), and cleanly bridges GitHub Actions' acyclic job model via workflow_dispatch for review iterations.
- **Bad:** Spawning a new workflow run for each review round introduces runner startup and checkout latency per round (to be measured in the first runs) and couples the Review job to the workflow file's workflow_dispatch input schema.
