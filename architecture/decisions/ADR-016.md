# ADR-016: The Design Stage Gets the Short Architecture Map by Default (amends ADR-003, from experiment E2)

## Status

Accepted. Amends ADR-003. Evidence: experiment E2 (`results/runs.md`, section E2).

## Context

ADR-003 left open how much architecture context the Analyst gets in Stage 2: the full `ARCHITECTURE.md` from A2 (108 lines) or a short map (`workflow/context/architecture_map.md`, 15 lines: components, the two rules, pointers to files). In A2, the full document raised cost without improving correctness.

Experiment E2 ran Stages 1 to 4 on copies of issues I1 to I4 with each variant, holding the models, prompts, checks and step limits fixed (8 runs, 1 trial each):

| | full ARCHITECTURE.md | short map |
|---|---|---|
| Runs whose code passed all hidden tests | 4/4 | 4/4 |
| Mean tokens per run | 215,870 | 208,764 |
| Stage retries (gate failures), total | 5 | 1 |
| Files changed | same file in every pair | same file in every pair |

## Decision

Stage 2 receives the short map by default. The full document stays available through the `arch_context: full` workflow input, and the Analyst can still read `ARCHITECTURE.md` from the checkout when the map points to it.

## Consequences

- Good: same correctness and the same file choices at slightly lower cost, and fewer stage retries (1 against 5). This repeats the A2 finding: the long document did not buy correctness.
- Bad: with one trial per issue, the difference in retries could be noise. The decision is cheap to reverse (one input) and should be revisited if a design that breaks an architecture rule ever reaches review.
- Note: the most expensive single run in E2 was a map run (I4: 26 Builder steps, 390K tokens). Cost per run varies more between runs of one variant than between the variants.

## Lectures

Lecture 5/6 (architecture knowledge management), Lecture 10 ("a map, not a manual"; treat context as a hypothesis and test it).
