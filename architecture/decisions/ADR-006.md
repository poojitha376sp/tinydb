# ADR-006: Zero-Cost Heterogeneous Model Routing Across Free Tiers (D6 — Models)

## Status

Superseded by ADR-012. (Proposed before any agent code was written; status set after the runs.)

## Context

Operating a multi-stage agentic pipeline under a strict zero-budget constraint rules out paid API billing accounts, while using a single model across both code generation and code review introduces correlated blind spots and self-preference bias.

## Decision

Route agent workloads across free-tier API providers using two distinct model families:

- **Analyst, Test Author, and Builder:** Gemini Flash via the Google AI Studio free tier (GEMINI_API_KEY), matching the lightweight, fast model profile validated in course notebooks for structured planning and iterative code repair.
- **Reviewer:** A different model family (e.g., Llama 3.3 70B or GPT-4o) accessed via GitHub Models (free tier, authenticated via the job's `models: read` permission), with Groq's free tier (GROQ_API_KEY) configured as an automatic fallback if GitHub Models throttles or errors.

## Alternatives considered

- **Paid frontier models (e.g., Claude Sonnet / o3-mini):** Rejected due to the hard $0 budget constraint without an attached billing account.
- **Gemini Flash for all roles including Reviewer:** Rejected because homogeneous model families share systematic blind spots, so a same-family reviewer is likely to miss the same errors the Builder made (to be tested in Experiment E1). Empirical results (HydraFusion) show that pairing a smaller generator with a cross-family second opinion recovers 74.7% of the accuracy gap to a large frontier model.

## Consequences

- **Good:** Achieves $0.00 operational cost while preserving genuine cross-family model diversity between the Builder and the Reviewer.
- **Bad:** Free-tier rate limits (requests per minute and daily token quotas across Google AI Studio, GitHub Models, and Groq) can throttle multi-step runs. Mitigated via exponential backoff with jitter, strict per-stage turn caps, and triggering issues one at a time during evaluation runs (ADR-010 still lets different issues run in parallel, which would share the same quota).

## Lectures

Lectures 1 and 9 (favoring smaller, efficient models for cost and energy), Lecture 8 ("agreement is not correctness; voting helps only when errors are independent"), and Lecture 10 (HydraFusion cross-family second-opinion gains).
