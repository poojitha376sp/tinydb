# ADR-003: Structured File Hand-Offs and Strict Information Hiding (D3 — Hand-offs)

## Status

Accepted. Amended by ADR-016 (the design stage gets the short architecture map, from experiment E2). (Proposed before any agent code was written; status set after the runs.)

## Context

Passing raw multi-turn conversation logs between agents inflates prompt sizes, degrades reasoning through irrelevant tool-call noise, and compromises role separation—particularly if the Reviewer or Builder sees upstream deliberation or hidden test assertions.

## Decision

Agents communicate exclusively through validated file artifacts (spec.md, design.md, diff.patch, test_report.md, review.md), never through shared conversation histories. Before passing any artifact downstream, the orchestrator validates its schema and structural completeness. Specific inputs are deliberately withheld per role:

- **Builder** receives spec.md, design.md, repository source files, and only the names and error tracebacks of failing tests—never the test source code itself.
- **Reviewer** receives only the raw issue text, git diff, and a read-only checkout at the PR's latest commit—deliberately excluding spec.md, design.md, test_report.md, and all agent transcripts so the Reviewer must derive expected behavior directly from the issue and catch cases where the Analyst misinterpreted the problem.

## Alternatives considered

- **Passing full conversation transcripts between stages:** Rejected because it exhausts free-tier token quotas, induces anchoring bias, and violates the requirement that the Reviewer remain blind to the implementer's reasoning.
- **Giving the Reviewer spec.md and design.md:** Rejected because reviewing against the Analyst's spec instead of the original issue would allow a flawed specification to pass undetected.

## Consequences

- **Good:** Minimizes token usage per turn, prevents the Builder from overfitting or gaming hidden test assertions, and enables the Reviewer to detect specification drift alongside implementation bugs. (Note: The granularity of architectural context passed in Stage 2—full ARCHITECTURE.md vs. a 30-line summary—will be empirically evaluated in Experiment E2.)
- **Bad:** If design.md omits subtle edge-case rationale discovered during Stage 1, the Builder cannot recover that context from the Analyst's private reasoning trace.

Lecture 4 (subagents return only distilled summaries), Lecture 7 (session loops: fresh context per task with durable state kept in files), and Lecture 8 (M6 pattern: evaluating drafts against hidden tests never shown to the generator).
