# ADR-017: Concurrency per Issue and Reviewed PR, /autose on Issues Only (supersedes ADR-010)

## Status

Accepted. Supersedes ADR-010.

## Context

ADR-010 grouped runs by issue number only. Two things broke that:

- Experiment E1 reviews five seeded PRs, each linked to its own issue, under two variants. A review of PR 15 and a full run of issue 14 share an issue number but must not block each other, and a later review must not cancel a pending one.
- `issue_comment` events fire for comments on pull requests too (GitHub treats a PR as an issue). `/autose` on a PR would have started a build for the PR's number as if it were an issue.

GitHub also disables Actions on a fresh fork until the owner enables them once in the Actions tab. Dispatches failed with HTTP 422 until then.

## Decision

- The concurrency group is `autose-<issue>-<reviewed PR or "main">`, with `cancel-in-progress: false`. Different issues, and different PR reviews of one issue, run in parallel; duplicates queue. GitHub keeps at most one pending run per group, so experiment scripts start one run at a time and wait for it.
- The gate job refuses `/autose` on a pull request with a message to comment on the issue instead.
- The trigger and role rules of ADR-010 are otherwise unchanged: the `autose` label (any user who can label) or `/autose` from OWNER, MEMBER or COLLABORATOR, and `sender.type == 'User'`.
- Setup instructions (README) include enabling Actions on a fork.

## Consequences

- Good: the E1 and E2 scripts dispatched more than 35 runs, several in parallel, without a collision; no active run was cancelled.
- Bad: parallel runs share the same free-model quotas (ADR-012), so the experiment scripts deliberately run one at a time per provider.
